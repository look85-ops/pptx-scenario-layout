# pptx-scenario-layout

Переупорядочивание слайдов управляющей презентации PowerPoint по карте сценария.
Проверено на раскладке корпоративных учебных презентаций на 200–500 слайдов:
перенос **от конца к началу** через PowerPoint COM (`MoveTo`) — только так
уже размещённые слайды не сбиваются последующими переносами.

Методика, выросшая из реального кейса: 202 слайда, 97 переносов, ~40 минут
вместо 2 дней ручной перетасовки. Валидация: порядок = карте, скрытые слайды
сохранены, контент не повреждён.

## Зачем

В корпоративных курсах сценарий часто приходит **после** вёрстки презентации.
Перетаскивать 200+ слайдов руками — это часы работы и ошибки: съехавшая
нумерация, потерянные скрытые слайды, дубли. Этот инструмент делает раскладку
по карте сценария быстро и проверяемо.

## Три принципа (подробнее в статье)

1. **Сценарий — источник истины.** Порядок секций берём из сценария, даже если
   в файле он другой. Если в сценарии есть ссылки на чужие модули — оставляем
   «дырки», их заполняет человек вручную в последнюю очередь.
2. **Сначала карта, потом перенос.** Составляем `target_order.txt` и валидируем
   его до переноса (полная перестановка: 0 пропусков, 0 дублей).
3. **Перенос от конца к началу через COM.** Обрабатываем позиции с последней
   к первой и двигаем только несовпадающие слайды (`SlideIndex` обновляется сам).

## Требования

- Windows + установленный PowerPoint (COM).
- PowerShell 5.1+.

## Использование

1. Составьте карту `target_order.txt` (см. пример в репозитории):
   строка N = исходный номер слайда, который должен оказаться на позиции N.

2. Запустите раскладку (создаст резервную копию `_original.pptx`):

```powershell
powershell -ExecutionPolicy Bypass -File layout.ps1 -PptxPath ".\deck.pptx" -MapFile "target_order.txt" -Backup
```

3. Проверьте результат:

```powershell
powershell -ExecutionPolicy Bypass -File validate.ps1 -PptxPath ".\deck.pptx" -MapFile "target_order.txt" -OriginalPath ".\deck_original.pptx"
```

`validate.ps1` проверит:
- количество слайдов совпадает с картой;
- порядок `sldIdLst` последователен;
- число скрытых слайдов (`show="0"`);
- если задан `-OriginalPath` — контент каждого слайда соответствует исходному
  (по нормализованному тексту; чистые числа — авто-номера — игнорируются).

## Известные грабли (проверено на практике)

- **Кодировка скриптов.** PowerShell 5.1 ломает `.ps1` с кириллицей без BOM.
  Если добавляете русские комментарии — сохраняйте файл в UTF-8 с BOM.
- **Имена файлов.** В путях может быть длинное тире «—», а не дефис.
  Ищите файлы по glob/`Where-Object`, а не хардкодьте строки.
- **Консоль.** Кириллица в выводе терминала показывается кракозябрами
  (cp866/cp1251). Пишите результаты в UTF-8-файлы и читайте их.
- **Перенумерация.** После COM-Save PowerPoint переименовывает slide-файлы:
  `slide{i}.xml` = новый i-й слайд. Это нормально — валидируйте по тексту,
  а не по старым номерам файлов.
- **Неиспользуемые слайды** — скрывайте (`show="0"`), а не переносите в конец,
  иначе человеку сложно ориентироваться в файле.

## Структура

```
layout.ps1         # перенос слайдов через COM по карте
validate.ps1       # проверка после переноса
target_order.txt   # пример карты
```
